# 交互方法、任务流程与控件状态

repair-1 · 2026-11-08 · 最新列表规则见 [修复交互规范](UI_REPAIR_PROPOSAL.md) 与 [修复演示](repair-prototype/index.html)。[旧可点击原型](prototype/index.html) 保留保存 / 冲突任务参考；[状态转换 SVG](design/09-state-flow.svg) 描述编辑边界。

用户已授权按本设计开始实现，并特别要求多选。实际实现与验证状态见 [实现记录](IMPLEMENTATION.md)。
Qt 的组件划分、输入去重、撤销边界与焦点实现遵循 [落地规范](QT_IMPLEMENTATION_STANDARD.md)。

## 1. 本轮采用的方法与具体决策

| 方法 | 当前决定 | 可验证的问题 |
|---|---|---|
| 任务驱动 | 先完成 PATH 添加、hosts 停用、备份恢复三条完整流程 | 能否找到下一步，是否在保存前理解变化 |
| 渐进披露 | Path 默认提供分隔项；类型、复杂分隔规则放到详情 / 高级区域 | 常用任务是否被低频配置干扰；高级入口是否可发现 |
| 状态驱动 | Clean / Dirty / Review / Writing / Invalid / Conflict / Failed / Draft 分开 | 文案、按钮、焦点、数据在每个状态是否一致 |
| 防误操作与恢复 | 可撤销编辑不重复确认；系统写入、丢弃修改、有损转换确认 | 用户是否理解暂存与系统保存，取消后能否接着编辑 |
| 键盘优先 | 字段按键优先，统一模型命令历史；Enter / Tab 暂存，Esc 撤销当前输入 | Del 不删除错误对象，焦点可见且可预测 |
| 组件与 tokens | 按钮 / 字段 / 提示条 / 差异行共用明暗语义色与间距 | 状态识别一致，暗色不会遗留亮色控件 |

“自动暂存”专指工作副本；文案不写“自动保存成功”。删除旧分隔项时保留 tombstone，
有效值立即更新。视图切换保留元数据；撤销不仅恢复文本，也恢复该项的身份和状态。

## 2. 任务流程

| 任务 | 用户动作 | 可见反馈 | 成功判据 |
|---|---|---|---|
| J01：添加 PATH 目录 | 选 Path → 新增项 → 输入 `C:\SDK\bin` → Enter / 失焦 → 保存 → 确认 | 新增项 +、有效项计数增加、1 个变量未保存、确认页含完整新旧值 | 演示目标含该目录；保存前目标不变；可撤销 |
| J02：停用本地映射 | 打开 hosts → 关闭 api.test → 可选撤销 / 重做 → 保存 → 确认 | 开关变关、工作副本出现注释、未保存计数、保存列出该行 | 演示目标中映射停用；未影响其他行 |
| J03：恢复误删变量 | 备份 → 核对差异 → 恢复到工作副本 → 保存 → 确认 | OLD_SDK 新增、DEV_MODE 将删除、Path 修改；恢复后仍未保存 | 演示目标含 OLD_SDK；系统范围不变；恢复可一次撤销 |

评审记录应区分“任务操作成功”和“用户理解正确”。原型脚本测试只能证明前者的模拟状态，
不能代替真人可用性测试。后续邀请使用者完成任务时，记录误点、回退、确认框数量、首次完成时间，
并让其回答“现在是否已经修改系统”。本轮不虚构用户测试数据。

## 3. 状态转换与返回路径

| 当前状态 | 事件 | 下一状态 / 数据处理 |
|---|---|---|
| Clean | 首次编辑 | Dirty；只改工作副本，未结束输入也阻止自动覆盖 |
| Dirty | 合法文本确认 / 排序 / 删除 | Dirty；自动暂存一次，更新统一撤销记录 |
| Dirty | 切变量 / 筛选 / 页签 | Dirty；结束合法输入后切换，无模态确认 |
| Dirty | 硬校验错误 | Invalid；保留输入，阻止保存，修正后重新计算 dirty |
| Dirty | 保存请求 | 先校验和复检，成功进入 Review；外变进入 Conflict |
| Review | 返回编辑 / Esc | Dirty；保留完整工作副本 |
| Review | 确认且 revision / 指纹匹配 | Writing；锁定修改，禁止重复保存 |
| Review | 目标或工作副本改变 | 原确认失效，重新校验 / Conflict |
| Writing | 全部写入且读回成功 | Clean；刷新基线、清对应草稿、显示结果 |
| Writing | 备份 / 写入 / 读回失败 | Failed；保留意图、逐项结果及恢复信息 |
| Failed | 再次审阅保存 | 重新读取和校验，再 Review / Conflict；不能直接复用旧 token |
| Dirty | 外部变化 | Dirty + 冲突提示；不自动替换 |
| Conflict | 暂不处理 | Dirty + 提示；编辑继续保留 |
| Conflict | 用我的修改覆盖 | 按变更集重建 Review，保留无关 env 项 |
| Conflict / Dirty | 重新载入 | 确认丢弃后 Clean；取消仍保留原状态 |
| Draft | 恢复 | Dirty；基线变化另进入 Conflict |

Dirty 是值差异和输入缓冲的组合；权限、主题、语言、焦点是正交状态，不能通过切换主题把 Dirty 清掉。
保存、备份与 hosts 整文件覆盖的详细约束以 F11–F14 为准。

## 4. 控件状态矩阵

| 控件 | Clean | Dirty | Invalid | Review / Conflict 弹窗 | Writing | Failed / 只读 |
|---|---|---|---|---|---|---|
| 保存到系统 | 禁用 | 启用 | 可定位错误，但不得写入 | 背景不可操作 | 禁用并显示进度 | Failed 可重审；只读禁用并说明 |
| 撤销 / 重做 | 按历史 | 按历史 | 先处理活动输入 | 背景不可操作 | 禁用 | Failed 保留历史；只读保留工作副本 |
| 字段输入 | 按目标能力 | 可编辑 | 保留错误文本 | 背景不可操作 | 禁用 | Failed 可修正；只读仅查看 |
| 分隔项删除 | 可写项可操作 | 可操作 | 不吞掉错误输入 | 背景不可操作 | 禁用 | 只读禁用；待删除项显示恢复 |
| 重新载入 | 直接读取 | 先确认丢弃 | 先确认丢弃 | 弹窗内动作 | 延迟到结果确定 | Failed 可确认重载 |
| 搜索 / 复制 | 可用 | 可用 | 不改变错误缓冲 | 模态范围内可用 | 根据实际任务只读 | 只读仍可用 |
| 页签 / 选择 | 可用 | 自动暂存后切换 | 保留输入并定位错误 | 背景不可操作 | 禁用 | Failed 保留内容；只读可切换 |

按钮与快捷键共享命令可用性。disabled 不是权限校验的替代，后续 C++ 命令入口仍需验证。
焦点环使用 accent、2 DIP；主动作与普通按钮有区别；普通文字、错误和提示均同时使用文本表达。

## 5. 何时确认

| 操作 | 确认规则 |
|---|---|
| 编辑值、移动分隔项、标记删除 / 恢复、切页 | 不确认，可撤销且目标未写 |
| 保存到系统 | 确认实际增改删；危险删除和超长风险在同一确认中点名 |
| 放弃工作副本、删除备份、归一化空格、有损转换 | 确认具体损失，默认安全动作 |
| 冲突覆盖 | 查看三快照后重新审阅变更；指纹变化必须重审 |
| 恢复备份 | 先在页面完整预览，再载入工作副本；最终保存仍确认。已存在编辑的保护依 F14 |

## 6. 原型范围与测试方式

`prototype/index.html` + CSS + JavaScript 是离线演示，数据只在内存；刷新重置，不使用 localStorage，
不调用 Win顺、注册表或文件 API；CSP 禁止网络连接。评审情境按钮只模拟外变、写入拒绝和只读。

已实现的原型交互：三条任务、单项排序 / 删除 / 恢复、原值切换、筛选、作用域、统一撤销重做、
保存审阅 / 取消、部分情境的冲突覆盖与失败重试、主题。未覆盖多选、所有分隔符、字节编码保真、
持久化草稿、真实备份文件、读回故障和系统权限，不得据此标记 T01–T48 通过。

离线 DOM 测试可验证事件和内存状态，不包含浏览器布局、焦点引擎、真实 IME、DPI 或屏幕阅读器。
浏览器自动验证受本地 URL 安全策略限制；详细执行结果见 [验证记录](VALIDATION.md)。

后续 Win顺 联调：先确认现有运行实例身份和已支持的插件加载方式；优先在该实例重载目标插件。
不为了测试新开 Win顺。原型验证阶段不改运行实例、插件安装和宿主配置。
