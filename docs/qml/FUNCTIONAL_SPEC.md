# EnvHosts QML 功能 spec

版本：repair-1 · 2026-11-08 · 基线：`eb35144`。用户已批准 [紧凑列表修复](UI_REPAIR_PROPOSAL.md)，当前状态见 [实现记录](IMPLEMENTATION.md)。本文件仍定义完整目标。

本文的“必须”指后续 QML 实现的验收要求，不表示只读原型已经支持。
每个 F 编号对应 [页面 SVG](README.md) 和 [T 测试用例](TEST_SPEC.md)。

## 1. 产品结构与视觉规则

保留 `env`、`hosts` 两个入口，各自复用一个独立窗口。环境变量窗口有“变量 / 备份”两页，
变量页用“用户变量 / 系统变量”按钮切换作用域，默认用户范围；hosts 窗口有“条目 / 原文 / 备份”三页。
切换页面不改变目标、不隐式保存。重复打开由 `kind` 找到已有窗口，并保留当前编辑。

| 区域 | 目标设计 |
|---|---|
| 窗口 | 默认 1120 × 760 DIP，最小 900 × 640 DIP；使用系统标题栏、缩放和最小化行为 |
| 主工具栏 | 当前目标、未保存变更数、重新载入、撤销、保存到系统；重做可在命令菜单及快捷键进入 |
| 内容 | 12 DIP 边距，6 DIP 基础间距；主列表和拆分项行高 28 DIP；按钮 26、输入及下拉框 28 DIP 起，随字体高度增长 |
| env 分栏 | 纵向可拖动，列表最小 160 DIP，详情最小 240 DIP；低高度时详情内部滚动，不能挤掉保存入口 |
| P02 展开模式 | 可将详情扩展到内容区域；返回列表后保留滚动、选择与待删除项；不新建窗口 |
| 表格 | env：名称 / 值 / 类型 / 修改状态；列宽可拖动，双击边界适应内容；长值省略显示，可在详情查看全文 / 复制；不可因省略截断模型值 |
| 窄窗口 | 工具栏次要动作进入“更多”；计数独立换行；PATH 列表保持全宽；禁止文字覆盖主按钮 |
| 状态栏 | 持久状态 + 权限 + 范围 / 行数；普通成功提示 4 秒后消失，错误与超长警告持续到解决 |
| 色彩 | 浅色：背景 `#edf1f5`、面板白、文字 `#16273b`、主色 `#185abd`；暗色见 P08 |
| 状态 | 新增“+”、修改“●”、删除“−”、只读“锁”、冲突“!”同时配文字；不只靠颜色 |
| 字体 | Segoe UI / 微软雅黑；值、原文用 Cascadia Code / Consolas；UI 字号 13–16 DIP |
| 模态交互 | 保存、冲突、恢复、放弃修改在所属窗口内；默认焦点落在安全动作，Esc 返回且不写入 |

QML 布局必须根据 availableWidth / implicitHeight 分配空间，不照搬 SVG 的绝对坐标。
默认配色与 P01 / P08 一致；不引入遮挡文字的透明玻璃效果。异常状态见 P07，转换见 P09。
控件状态、焦点与任务流程详见 [交互规格](INTERACTION_SPEC.md)。

## 2. 功能要求

### F01 — 生命周期与入口（P00，T01–T02）

- 保持现有插件 ID、命令、action、JSON-RPC framing 与数据目录；`query` 不打开窗口、不写目标。
- 首条“进入交互式编辑界面”才触发窗口。env 与 hosts 各最多一个实例；重复打开恢复最小化并尝试激活，不永久置顶。
- 外部传入 filter / select：先结束合法的当前文本输入并自动暂存，再应用视图变化；不弹提交确认、不重建模型。IME 组合中延迟处理，硬错误保留输入并提示定位。
- Qt GUI 线程运行窗口与模型适配；协议线程通过现有 bridge 入口派发；关闭最后一个窗口不停止 resident 协议服务。
- QML 加载失败返回明确错误和 `keep`，不报成功；宿主 shutdown 先停止新任务、持久化草稿、关闭窗口，再结束协议线程，禁止互相等待造成死锁。

### F02 — 数据加载、范围与列表（P01/P03，T03–T04）

- 区分 Loading、Ready、Empty、Error；空数据、无筛选结果和读取失败不得共用同一句文案。
- env 用“用户变量 / 系统变量”按钮切换，默认用户范围，不提供混合全部视图；读取名称、原值、类型、作用域、可写状态；同名用户 / 系统变量独立展示；`showSystemVars=false` 时不露出系统行。
- 每范围保存筛选、选择 / anchor、当前行、排序与滚动；批量命令仅作用当前可见范围，跨范围修改统一保存且在复核中列明。
- 名称 / 值 / 类型单元格双击分别聚焦对应编辑，状态双击仅查看说明；表头边界双击只调整列宽。排序和列宽不进入数据 undo。
- 列表初始顺序与基线相符，env 在范围内按名称不区分大小写排序，hosts 保持文件行顺序。
- 每行具有稳定 session rowId；名称修改、筛选、移动、删除标记、撤销不让 UI 选择落到另一对象。
- `maxResults` 只限制启动器结果，不截断编辑器模型；表格使用虚拟化，渲染数量随可见区域变化。

### F03 — 筛选、选择和批量（P01/P03，T04–T06）

- env 搜索名称 / 原值，hosts 搜索 IP / 主机名 / 注释；Unicode 查询可用；输入不中断详情 IME 组合。
- Ctrl+点击增减选择，Shift+点击或 Shift+方向键扩展区间，Ctrl+A 选择当前过滤视图；焦点行与选择集分离。
- 改筛选后保留仍可见的选择并清除隐藏选择；当前行隐藏时选择下一可见行；分隔项文本按 F05 自动暂存，其逐项元数据继续归属原变量。
- 新增行在当前可见顺序最后一个选中项后插入，无选择时追加；保留其余当前排列并退出列排序。清除使其不可见的过滤词，滚动并进入名称 / IP 输入。删除已存在行先标记，可恢复；删除未保存新行立即移除。
- 批量命令只处理选中可操作行；跳过只读行、注释标题，显示“处理 N / 跳过 M”及原因。一次批量为一次撤销。
- Ctrl+C：env 输出 `NAME=value`，hosts 输出原行；按可见顺序复制，包含选择中的待删除行，便于核对；只在显式命令触发时操作剪贴板。

### F04 — 环境变量原值编辑（P01，T07–T08）

- 字段：名称、类型、原值。已有 REG_SZ / REG_EXPAND_SZ / REG_MULTI_SZ 保真；不因有 `%` 就重写既有类型。
- 新建采用当前按钮范围，默认打开用户范围；用户显式选择类型。重命名表现为旧名删除 + 新名新增，确认列表明确显示；大小写冲突按当前逻辑校验。
- REG_MULTI_SZ 使用专用“每行一个字符串”的原值视图；保留字符串顺序和尾部终止语义，不使用 PATH 分隔项模式。旧适配层无法无损转换时显示格式错误，不猜测内容。
- 原值复制与展开值复制独立；展开仅用于预览 / 复制，不写回存储，也不自动解析为路径。
- 原值编辑在 400 ms 空闲、焦点离开或保存时合并一次命令；输入中不因筛选变化移走该行。撤销回到基线时清除 dirty。

### F05 — 分隔项自动暂存与删除（P02/P09，T09–T13）

- 使用一个窗口级命令历史；每个变量的 `PartsState` 持有 rowId、revision、分隔符和 stable partId / value / isNew / pendingDelete。它属于工作副本，不是每次聚焦临时重建的 UI 缓存。
- 首次进入列表解析工作值；合法文本确认、移动、删除和恢复立即更新工作副本及变更摘要。值由非 pendingDelete 项合并；不额外提供“应用到变量”或“重置此列表”按钮。
- 对已有项按 Del 标记 `pendingDelete`，行留在列表、带“恢复此项”，再次操作恢复；对新增项按 Del 立即移除。混选时分别处理，整批只形成一次命令。
- Enter / Tab / 焦点离开自动暂存本次文本；Esc 还原本次尚未确认的输入。新增项立即进入编辑；IME 组合期间 Enter 不触发暂存。未结束输入也纳入草稿和 dirty 指示，不能因此被外变刷新覆盖。
- Alt+↑/↓ 按所选项作为稳定块移动并保持相对顺序；partId、删除标记、新增标记与值一起移动；越界移动无副作用、不增加 undo。
- 文本确认、单次移动、单次删除 / 恢复各为一次模型命令。撤销和重做恢复值与 PartsState 的同一份快照；普通切页、聚焦、筛选不重建或二次应用删除索引。
- 切换变量、原值模式、范围、筛选或备份页时自动暂存合法输入，不弹“应用 / 放弃”确认。遇到硬错误保留缓冲并定位；只有明确丢弃、有损转换和实际系统保存需要确认。
- 从列表进入原值显示当前有效项合并值；仅切换视图不清掉待删除元数据。用户直接改写原值或更换分隔符时形成一次包含前后元数据的命令；按新值重建列表，undo 能恢复原来的待删除项。
- Ctrl+S 结束合法输入后进入 F11；取消保存仍保留已暂存工作副本。任何自动暂存都不写注册表 / hosts，不使用“自动保存成功”误导用户。
- “删除整个变量”明确标记整行、清空并禁用详情展示，保留可恢复快照；这是可撤销编辑，无额外模态确认，真正保存时点名所有删除。恢复后值与分隔项元数据一致。

### F06 — 分隔符规则（P02，T14）

- Path 默认 `;`；支持分号、逗号、冒号、制表符、竖线、空格及非空自定义字符串。
- 使用现有 split / join 语义并增加往返测试：引号内分隔符不拆；非空格模式保留空段、重复项与首尾分隔符；禁止自动去重 / 修剪 / 排序。
- 切换分隔符先自动暂存当前合法文本，再将当前有效工作值按新分隔符解析；整个转换一次撤销，包含原先待删除元数据；普通无损切换不确认，未编辑 round trip 字节相同。
- 空格模式必须先显示归一化说明，Path 额外举出 `C:\Program Files` 会被拆开的例子，默认取消；确认后才允许该有损操作并保留一次撤销。
- 自定义分隔符 Enter 应用，Esc 取消；空分隔符硬错误；引号不匹配按现有解析语义保留原文并提示，不擅自补引号。

### F07 — 校验与长值（P01/P02/P07，T15–T17）

- 空名、非法 `=` / 控制字符、同范围重名、非法类型等沿用 `logic.h` / 模型的规则；UI 逐字段定位，保存总览列出硬错误。
- 显示值的 UTF-16 code unit 数，包含分隔符，不把 emoji 计为一个单元；90% 以上琥珀色，超过 32,767 为红色。
- 超长值在编辑器中是**需要明确确认的警告**：注册表可写，但进程消费可能受限制；未测的消费上限不承诺。确认页点名变量与超出量。
- 启动器 `env:set` 沿用其硬限制；不能因 QML 可确认而放宽无警告界面的协议路径。输入 / 粘贴 / 草稿 / 显示均不得静默截断。

### F08 — hosts 条目（P03，T18–T20）

- 支持 IPv4 / IPv6、多主机名、行尾注释、添加、编辑、删除恢复和批量启停；数据校验采用现有纯逻辑。
- 独立注释、空行和未知行只在全文显示，底层保留原位置和原始字节。合法 `# IP 主机名` 作为停用映射显示，行尾注释保留。
- 启用用绿色符号与文字，停用用琥珀色符号与文字；待删除行使用 redbg 整行背景、红色边标及“待删除”。选择边框不覆盖删除背景。
- 后续启用行重复映射同一主机名时标 `!` 和重复计数，展示相关行号；停用行不计入启用冲突；不自动删除重复。
- Space 在条目列表上批量启停：存在可操作停用项则整批启用，否则整批停用；待删除项跳过。复选框 Space 只切选择；Enter / F2 按当前列进详情。

### F09 — hosts 原文与字节保真（P04，T21–T23）

- 原文页为完整等宽文本，具有行号、编码、换行和末尾换行提示；只读时原文同样只读。
- 原文编辑有局部文本撤销；离页、保存、关闭前将完整缓冲应用成一次模型命令。取消关闭后不重复应用。
- 未修改的内容保存后逐字节一致，包括 BOM、CRLF / LF / 混合换行、末尾换行、空白和未知行；不能只靠 TextArea 规范化后的字符串重建全文件。
- 适配层必须保留原始字节 / 行 ending 映射；只有用户修改的行才能重新编码；新增行采用文件主要换行方式（数量相同用 CRLF）。
- UTF-16 BOM 输入返回 E_HOSTS_UTF16，禁止写回；对无法无损解码的数据明确只读 / 错误，保留原文件。语法非法的原文行允许保留，但不会伪装成合法映射。

### F10 — 读写能力（P03/P07，T24–T25）

- 可写性来自实际目标探测 / 操作结果，管理员 token 只作为说明；HKCU、HKLM、hosts 能力分别判断。
- 不可写目标仍可搜索、复制、查看备份；编辑、删除、恢复到该目标的按钮禁用并有可访问原因。hosts 可打开外部编辑器。
- 权限变化时刷新 capability；保存前再次探测。系统只读时不得把系统编辑改写到用户范围，也不能悄悄跳过并宣布全部成功。
- 不主动弹 UAC；权限说明沿用宿主管理员启动 + 插件确认流程。实际宿主授权仍需要 T48 集成验证。

### F11 — 保存事务与结果（P06，T26–T30）

1. 结束当前合法输入，自动暂存文本 / 原文缓冲；分隔项值已经随命令进入工作副本，禁止再按旧删除索引裁剪；硬错误立即定位且不写目标。
2. 固定 `modelRevision`，计算增 / 改 / 删清单；无变更为 no-op，不创建备份。
3. 读取当前目标与能力；存在外部冲突进入 F12。确认页列出目标范围、重命名、删除名称及超长风险。
4. 用户确认产生绑定 revision、change-set 摘要、目标指纹的单次 confirmationToken；任何工作副本更改使 token 失效。
5. 在统一写入服务中取得 `g_writeLock`，重新读取实际涉及范围 / hosts 并比较确认指纹；不同则释放锁并重新打开差异，不能沿用旧确认。
6. 先保存可恢复备份并检查写入 / 关闭 / 读回结果；失败立即终止。env 备份覆盖实际会写的范围；hosts 为完整原始字节。
7. 串行应用确认的变更集；对 env 逐项记录成功 / 失败 / 未执行，首次失败停止后续写入；hosts 延续保留 ACL 的原地写入策略。
8. 读回验证目标，env 广播设置变更并记录广播结果。只在全部写入及读回成功后设为 Clean、更新基线并移除已对应的草稿。
9. 写入失败 / 部分成功 / 读回失败，显示准确结果与备份位置；保留用户意图和草稿，以原基线 / 意图 / 实际读回建立差异，禁止清空 dirty 或自动重试。广播失败显示“已保存，广播失败”，不谎称存储失败。

Writing 时禁用编辑和重复保存；关闭请求延迟到本次结果确定后再处理，不中断已经开始的系统写入。
进度用于反馈，不能假装已经完成。所有写入口（启动器、QML、恢复）必须共享写锁和备份错误处理。
注册表多项写入、hosts 原地写入均不宣称原子；本进程锁无法锁住任意外部编辑器。
最终复检之后仍存在外部写入竞争窗口，应在读回中尽量检测，不承诺杜绝外部同时写入。

### F12 — 外部变化与冲突（P06/P07，T31–T32）

- 前台约 2 秒、失焦约 10 秒轮询；输入会话、模态框、保存事务中暂停自动替换，退出后重新检查。
- Clean 自动重载且尽量保持 rowId / 位置；Dirty 仅显示差异条，不替换编辑；未结束的字段、分隔项或原文输入也属于 Dirty。
- env 按将写的作用域比较：只写用户时系统变化不阻塞；写系统时必须检查系统基线。不得用用户指纹替代系统检查。
- 三快照对比包含基线、我的意图、当前目标，支持相同 / 仅我改 / 仅外部改 / 双方一致 / 冲突，涵盖新增、删除和重命名。
- “暂不处理”关闭差异且保留提示；“重新载入”确认后丢弃编辑；“用我的修改覆盖”按我的**变更集**重建保存计划，保留外部无关变量，随后重新进入保存确认。
- hosts 原文变更无法安全拆为变更集时，覆盖意味着整文件替换，必须列出将丢弃的外部差异；图中 env 的“保留外部无关项”不能套用 hosts 整文件覆盖。
- 覆盖不跳过权限、校验、备份和最终指纹复检；期间再次外变则重新审阅。不实现自动三方合并。

### F13 — 草稿与关闭（P07，T33–T34）

- Dirty 每 30 秒及关闭 / shutdown 前写入数据目录草稿，不触发目标写入；包含 PartsState、未结束的输入缓冲及未合并原文。
- 建议新草稿 envelope：`schemaVersion: 2`、kind、targetIdentity、savedAtUtc、baseSnapshot / 指纹、工作副本及其分隔项元数据、输入缓冲；明确标记这是待实现格式。
- 保留现有 `drafts/env.json` / `hosts.json` 读取兼容。旧草稿缺少原基线时不能以当前目标伪造“原”：提示基线未知，恢复后必须核对目标与完整变更确认。
- targetIdentity 匹配展开后的 hosts 路径或注册表范围 / 子键。目标不符的草稿不得套用；保留文件并说明。
- 使用临时文件写完并校验后替换草稿；写入失败保留上一份并常驻提示。损坏 / 未知 schema 不当作“没有草稿”。
- 正常关闭 Dirty 窗口：保存到系统 / 保留草稿并关闭 / 放弃修改并关闭 / 取消。放弃需确认，草稿保存失败禁止假装已保留并关闭；shutdown 失败则 stderr 记录错误并保留最近成功草稿。
- 重开显式询问恢复 / 丢弃 / 稍后；恢复后仍 Dirty，基线变化时进入 F12；只有成功保存或明确丢弃才清理相应草稿。

### F14 — 备份浏览与恢复（P05，T35–T38）

- 左侧时间倒序列表显示用户 / 系统范围标签；支持全部 / 用户 / 系统范围过滤（P05 展示全部状态）。UTC ID 不改，本地时区只影响时间显示。
- 右侧按变量 / 行预览和搜索，以 `= / ~ / + / −` 标记相对于当前工作副本的差异，并明确比较基准。包含系统范围的备份需选择恢复范围并验证可写性。
- 选中恢复先显示实际增改删，尤其“当前多出”意味着将删除；有现存编辑时提供取消或先保留恢复前工作副本草稿。
- 恢复前先备份当前目标，并保留现存未保存编辑的恢复点；备份失败不继续。恢复作为一次 undo 命令载入工作副本，**目标仍未写入**；后续保存再次按 F11 备份。
- 用户范围备份不改变系统范围；旧备份缺 scope 按历史用户范围读取并标识；损坏、读取失败与合法空集合必须可区分。恢复合法空集合时明确列出全范围删除。
- 导出 env 为 JSON，hosts 为逐字节 `.hosts`，保留现有 `WS_DATA_DIR/exports` 位置；失败显示原因。删除备份需确认准确 ID，不接受路径穿越。
- 保留数量按现有 backupCount；新备份成功持久化后才可清理最旧备份，本次故障恢复所需备份不能被本次清理删除。

### F15 — 撤销、焦点与键盘（所有页，T39–T40）

| 焦点 | 快捷键 | 行为 |

| 非输入区 | Ctrl+F / Ctrl+Tab / Shift+Ctrl+Tab | 筛选 / 前后切页 |
| 变量列表 | Ins / Ctrl+N、Del、F2 / Enter | 新增变量、标记删除 / 恢复、进入详情 |
| hosts 列表 | Ins、Del、Space / Enter、F2 | 新增、删除 / 恢复、启停、详情 |
| 分隔项列表 | Ins / Ctrl+N、Del、Alt+↑/↓、Enter | 新增项、项删除 / 恢复、移动、编辑项 |
| 文本输入 | Del / Backspace / Ctrl+A / Ctrl+C | 只操作文本，不冒泡成整行命令 |
| 输入 / IME | Enter / Esc | 先交给组合输入；非组合态提交 / 取消当前编辑 |
| 活动文本输入 / 原文缓冲 | Ctrl+Z / Ctrl+Y | 文本级 undo / redo；结束输入后使用统一模型历史 |
| 分隔项列表非输入区 | Ctrl+Z / Ctrl+Y | 统一模型历史，同时恢复值与逐项元数据 |

### F16 — 状态和错误反馈（P07，T41–T42）

至少区分读取失败、无结果、文件不存在、UTF-16 / 解码失败、权限拒绝、文件占用、备份失败、草稿失败、
验证失败、外部冲突、部分写入及读回失败。错误有稳定 code、用户文案、目标范围和可执行下一步。
能保留内容时不得清空视图。值和 hosts 内容不进入诊断日志；原始错误码可以进入 stderr。
读取失败不能使用旧缓存宣称数据已同步；正在读取有可见 busy 指示。

### F17 — 可访问性与 DPI（P01/P08，T43–T44）

所有输入有 label / accessibleName，图标按钮有名称，禁用原因可读；表格读出行名、范围、状态。
键盘能完成添加、编辑、删除恢复、分隔项排序、保存取消、备份恢复；弹窗正确捕获并还原焦点。
焦点环与选中背景区别明显；普通文字对比度目标 4.5:1，控件边界 / 焦点至少 3:1。
100/125/150/200% 缩放、跨显示器移动、最小窗口和长中英文提示都不得遮挡主操作。

### F18 — 主题、语言和设置（P08，T45–T46）

- 沿用 `uiLanguage=auto/zh-CN/en-US`，固定设置优先，auto 跟宿主；已经打开窗口即时刷新文案，保留输入、选择、撤销和草稿。
- 宿主 appearance 更新明暗主题；不重建 session。P08 给出暗色 tokens，所有页和模态框共用。
- 保留 hostsPath、backupCount、maxResults、showSystemVars；非法设置按既有默认处理。hostsPath 变化时旧目标的未保存编辑必须先决策，旧草稿不可套到新目标。
- 设置和语言切换不获得额外系统写权限，不触发隐式保存。

### F19 — 性能与协议（P00，T47）

以下为新版本目标，尚未测量：10,000 个合成变量 / 10,000 行 hosts，20 次测量下过滤到绘制 p95 ≤100 ms，
热窗口激活 p95 ≤200 ms，冷窗口可交互 ≤1.5 s；超过 150 ms 的任务显示 busy 并保持事件循环响应。
记录模型构建、首帧、首个可交互帧、工作集峰值、包体和数据规模，不用旧文档数字冒充新结果。
manifest 当前 `timeoutMs=1500`、`memoryMB=64` 是集成约束；需要通过真实宿主确认 QML 的行为。
超出预算时阻止正式替换，先优化或单独评审 manifest 变更，不能自动提高限制。

### F20 — 构建、分发与迁移（所有页，T48）

沿用 `ENVHOSTS_QML_EDITOR` opt-in 与 `build-qml/bin` 输出；Qt 运行时由插件独立携带。
不依赖开发机 PATH / Qt 安装或宿主 Qt；QML 资源打包，Basic style 作为既有技术基线。
真实安装验证包含 clean machine、Qt 模块缺失、权限确认、数据沿用、卸载 / 禁用和宿主退出。
发布前再同步版本和双语 README；不能把本设计提案当可发布 QML 完整版。

后续本机联调优先复用正在运行的 Win顺，通过其支持的插件加载 / 重载路径验证；不得为方便测试启动另一套 Win顺 实例。
用户已明确开始实现，尤其要求多选。联调保留现有工作与配置，不为测试另起 Win顺。
真实安装、卸载和宿主退出测试属于后续独立验收环境；需要影响正在使用的实例时先说明具体影响和恢复方案。

## 3. 模型与实现接口提案

以下是职责拆分，实际 API 落点见追踪表和实现记录。
详细的组件 / 命令 / 数据契约和实施门槛见 [Qt 实现规范](QT_IMPLEMENTATION_STANDARD.md)；
[追踪表](qt-traceability.json) 将每个 F 映射到页面、组件、命令与 T 用例，当前验收状态按实际证据标记为 PARTIAL 或 NOT_RUN。

| 层 | 职责 / 约束 |
|---|---|
| `logic.h` / `editor_model.h` | 解析、字节保真、校验、diff、工作副本和 undo；可独立测试 |
| `EditorSession` | 每目标一个 session；revision、rowId、选择、PartsState、TextEditBuffer / RawEditSession、统一 undo、状态和草稿 |
| `EditorRows` / `PartsModel` / `BackupModel` | QAbstractListModel / model adapter；roles 包含 rowId、scope、rowState、writable、validation；GUI 线程更新 |
| `EditorBridge` | 暴露属性与命令；不让 QML 自行拼接写盘指令、不暴露任意路径写方法 |
| `WriteService` | 串行读 / 探测 / 备份 / 冲突 / 写入 / 读回；复用 native store 并补齐可观测错误 |
| QML pages / controls | 渲染与焦点；格式、存储和确认有效性由 C++ 决定；后台结果带 revision，过期结果不可应用 |

属性建议：`kind, page, loading, dirty, hasPendingEdits, canSave, canUndo, canRedo, capability,
currentRowId, selectionIds, validationSummary, externalChange, saveState, status, theme, locale`。
命令建议：`selectRows, editField, addRow, toggleDelete, ensureParts, editPart, moveParts, finishTextEdit,
setRawText, requestSave, confirmSave, requestReload, requestRestoreBackup, resolveDraft`。
写入结果必须区分 `Succeeded / StoredButBroadcastFailed / Rejected / Conflict / PartialFailure / ReadbackFailure`，
同时带每项结果、可用备份 ID 和当前目标指纹，不只返回 bool。

`native.h` 的现有 BackupStore 写入路径没有完整错误返回，读取某些失败会折叠为空值；
它们是迁移审计点，必须在复用前补齐，不能由 QML 猜测成功。现有 `WM_APP_*` 测试 hook 只属于 GDI，
不得冒充 QML 行为测试。
