# envhosts：搜索结果逐项动作改进方案

[English](sdk-upgrade-plan.en.md)

## 改动原因

源码已为变量和 hosts item 声明部分动作，需要补齐的是动作可发现性、正确目标与实际可执行性，并能直接打开编辑器定位当前项。

当前动作路径存在具体问题：

- 变量编辑填回 `env:set NAME=value` 时丢失作用域，编辑行和保存走用户范围，系统变量可能被误写成同名用户变量。
- 行内保存根据新值推断注册表类型，没有保留原类型。
- hosts 在区分动作之前检查写权限，复制整行和打开文件也被只读限制挡住。
- 重复 hosts 查询 ID 带 `-2` 后缀，但动作只查基础 ID；删除确认又按原文匹配第一条，无法保留选中记录身份。
- 没有独立展开值的变量也显示复制展开值动作。

## 逐项动作

| 结果 | 默认动作 | 菜单其他动作 |
|---|---|---|
| 环境变量 | 打开编辑器并定位作用域和变量名 | 复制原始值、不同的展开值、变量名、NAME=value；支持的简单值行内编辑；删除 |
| hosts 记录 | 根据状态显示“启用”或“禁用” | 编辑并定位记录；复制 IP、主机名、整行；打开 hosts 文件；删除 |
| 分组或纯注释 | 不执行记录修改 | 适用时复制原文 |

保留 Ctrl+Enter 复制快捷键；更多能力放入结果菜单，菜单按具体条目生成。

## 实现方案

1. 复用 `editorwin::OpenArgs.select` 的作用域／变量名和 hosts 行号定位。通用编辑器入口与逐项编辑共享建窗参数逻辑。
2. 编辑已有变量时，全路径保留作用域、名称和原类型，写入及备份使用对应范围。系统写入失败明确返回权限结果。
3. 行内编辑限于现有单行语法支持的值。PATH 分隔项、多行或特殊类型、显式类型修改使用现有编辑器。新建变量命令保持其明确的默认作用域和类型语义。
4. 复制和打开文件先处理，写权限只在启停、删除等修改动作中检查。打开文件不承诺外部编辑器自动提权。
5. 查询、编辑定位、启停和删除确认共用 hosts 记录解析器，携带原行、位置及重复出现次序。执行前重读并核对目标，记录改变时刷新并提示，不误改另一行；直接比较文本，不增加哈希。
6. 删除确认保留完整目标身份，只有明确的确认动作执行删除，取消及其他动作均不提交。
7. hosts 启停成功后保持列表打开并刷新，保留筛选，在宿主支持时定位更新后的记录。已有编辑器外部更新处理保留未保存工作。
8. 展开值相同则省略对应复制动作；只读项仍可复制和查看，写操作给出准确权限结果。

## 插件配置

五项偏好继续放在宿主卡片，无需专用设置窗口。最大结果数沿用 1–200；备份数确认现有保留语义后再添加范围和单位。数值解析不能因 `std::stoi` 异常使查询失败。

`hostsPath` 保留文本及 `%VAR%` 展开能力，不直接换成仅文件选择器。独立编辑器继续承担复杂数据编辑。

## 验收标准

- item 动作集合与变量、启用／禁用 hosts、分组类型匹配，真实宿主菜单可以调到对应动作。
- 用户与系统存在同名变量时，编辑不混淆范围；类型仅在用户明确修改时改变。
- 只读 hosts 能复制和打开，修改得到准确权限结果。
- 两条相同记录中的第二条可以单独编辑、启停和删除。
- 查询后目标发生改变，不修改其他记录。
- 编辑器新开或已打开时均能定位当前项，不丢未保存编辑。
- 查询不写注册表、hosts、剪贴板，也不开窗口。

自动验收使用现有测试注册表键和临时 hosts，不操作真实系统配置。
